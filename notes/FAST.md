# FAST: faster exact solver for the anchored / confined request game

Code (all new, `compute/fresh_c/` untouched): `compute/fast/engine.js` (engine), `anchor_fast.js` (anchor selection + certificates, same JSON format as `anchor_select.js`), `anchor_table_fast.js` (anchored table as `anchor.js`), `fast7.js` (7-request game with one fixed edge on N points = `exact7d.js` / `exact7N.js`), `difftest.js` (random differential test against the original `Game`).

## What changed (semantics unchanged)
- Typed arrays, integer edge invariants for the canonical form, O(n) relevance filter (superset bitsets), exact-key open-addressing transposition table (full key stored, no hash collisions; table is reset when over its entry cap).
- Killer replies per node; counting-sort request ordering (same heuristic score).
- Level 5 (five edges, last two rounds) is decided without the original request x reply enumeration:
  - reply forced (|D|-T <= k): exact enumeration of the fully requested type set B with spare-budget allocation, pruned by cnt(N(P)) > T (`forced5`);
  - otherwise the original closed form (`lastRound`, including its bail rule); on bail the exact fallback enumerates requests and replies by *support sets* (`win5`/`refute5`), not by count vectors.
- Certificates: moves are re-derived on demand (`moveFor`), so the table stores only booleans.

## Validation
- `difftest.js`: 422 + 588 random states at levels 3-5 (k = 4..8), pair bound on/off, fast vs original `Game`: 0 mismatches (first batch before `forced5`; second batch with `forced5`; the last `win5` rewrite experiment was reverted, not used).
- Anchored tables identical shape-by-shape (list of adversary-winning shapes) to `anchor.js` for (4,3), (5,4), (6,4), (6,5), (7,6), (8,7), (8,6).
- Anchor selection reproduces the notes: (6,5), (7,6), (8,7): J=4 requester wins; (8,6): adversary for J=3,4,5 (same state counts 14, 399); (5,4): adversary J=3,4,5; (9,7): adversary J=3,4 with the same nine losing shapes.
- 2k-point / N-point game: (6,5,12) R, (7,6,14) R, (8,7,16) R, (9,8,18) R, (6,4), (7,5), (8,6,15) and (8,7,20) adversary, as originals (originals at N=2k: (8,6) 346 532 states).
- Certificates for (6,5), (7,6), (8,7), J=4, regenerated by the fast solver and checked by the unchanged independent `cert_check.py`: all VERIFIED (88/206/240 her nodes; 17/27/36 winning shapes). Files: `compute/fast/certs/`.

## Next step that would matter
The remaining cost is the unforced level-5 node. A request-pruning bound valid for |P| > k (P = types not fully requested) is missing: the adversary then chooses a support, so cnt(N(P)) is not a lower bound. A counterexample-guided search over requests (tried, `win5` with stored refuting supports) was slower than plain enumeration because a refuting support is killed by a single cheap request, so each stored support prunes little. Worker parallelism was not added: the anchor-selection search needs shapes on demand; independent instances were run as separate processes instead (at most 3).
